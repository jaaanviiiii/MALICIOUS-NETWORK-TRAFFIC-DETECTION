## 2. Data Leakage & Splitting Methodology Audit

### 2.1 Preprocessing Leakage
- **Issue Found:** In initial data preparation, infinite values (`±inf`) generated by zero-duration flows in `Flow Bytes/s` and `Flow Packets/s` were replaced by the global median computed over the merged dataset before train/test splitting. In formal machine learning theory, computing statistics over the combined dataset leaks test set distribution into the training set.
- **Correction Made:** 
  1. The corrupt rows with infinite values represented only 142 out of 129,016 flows (0.11%). These 142 corrupted flows were dropped from the dataset, eliminating the need for pre-split global imputation.
  2. The `StandardScaler` is fitted strictly on `X_train` (`scaler.fit_transform(X_train)`) and only applied (`scaler.transform(X_test)`) to test and real-time inputs.
  3. Feature medians for future missing value handling in inference are calculated exclusively from `X_train`.

### 2.2 Duplicate Flow Analysis
- **Issue Found:** CIC-IDS2017 contains duplicate and near-duplicate network flows resulting from repeated retransmissions, TCP keep-alives, and port scan probes. An audit revealed **10,165 exact duplicate records (7.88%)** within the sampled dataset. When doing a random stratified split without deduplication, identical flows appear in both training and test sets, allowing tree-based classifiers to achieve near-perfect memorization scores.
- **Correction & Verification:**
  - A benchmark test on a strictly deduplicated dataset (118,847 unique flows) yielded:
    - **Random Forest Accuracy:** 99.75%
    - **Weighted F1-Score:** 99.75%
    - **Macro F1-Score:** 99.74%
  - This confirms that Random Forest's high discriminative power is genuinely driven by robust feature splits (packet length variance, flow duration, initial window bytes), rather than purely memorizing duplicates.

### 2.3 Evaluation Bias: Random Stratified Split vs. Day-Based Split
- **Audit Assessment:** The current 80/20 random stratified split produces an in-distribution evaluation (testing whether the model recognizes known attack families generated on the same network topology).
- **Cross-Day Generalization Experiment:**
  - We trained Random Forest on Tuesday & Wednesday (Patator Brute Force, DoS Hulk, DoS GoldenEye, Slowloris, Heartbleed) and tested on Thursday & Friday (PortScan, DDoS, Botnet, Web Attacks, Infiltration).
  - **Results:**
    - Overall Cross-Day Accuracy dropped from **99.77% to 67.70%**.
    - PortScan recall dropped to **0.12%**.
    - Botnet recall dropped to **0.00%**.
    - Infiltration recall dropped to **0.00%**.
    - DDoS recall was **62.89%** (benefiting from structural similarity to DoS).
- **Academic Conclusion:** Supervised classifiers are bound by their training distributions. The random stratified split is appropriate for multi-attack classification of known families, but in operational environments, unseen zero-day attacks require anomaly detection or continuous retraining.

### 2.4 Feature Target Leakage Verification
- The 69 features in `models/selected_features.json` were audited. Target labels (`Label`, `Clean_Label`, `Attack_Category`, `Is_Malicious`) and derived target identifiers were fully excluded. Only network layer flow features (packet size statistics, flag counts, window sizes, inter-arrival times) are used.

## 5. Multiclass Classification Architecture

To ensure the system does not make unfounded claims about identifying specific attack types from a binary model, a dedicated **Multiclass Random Forest Classifier** (`models/multiclass_rf.joblib`) was trained on 8 categories:

```
Attack Category Mapping:
- BENIGN      : Normal safe network traffic
- DoS         : DoS Hulk, GoldenEye, slowloris, Slowhttptest, Heartbleed
- DDoS        : Distributed Denial of Service
- PortScan    : Port Scanning / Reconnaissance
- Brute Force : FTP-Patator, SSH-Patator, Web Attack Brute Force
- Web Attack  : Cross-Site Scripting (XSS), SQL Injection
- Botnet      : Bot traffic
- Infiltration: Network Infiltration
```

### Multiclass Classification Performance (8 Classes):
- **Overall Multiclass Accuracy:** **99.28%**
- **Weighted F1-Score:** **99.12%**
- **Macro F1-Score:** **88.43%**

| Category | Precision | Recall | F1-Score | Test Support |
| :--- | :---: | :---: | :---: | :---: |
| **BENIGN** | 99.74% | 99.81% | 99.77% | 14,200 |

## 7. Remaining Limitations & Future Recommendations

1. **Payload Invisibility:** Flow-based statistics do not inspect packet payloads. Payload-level web attacks (SQLi, XSS) require complementary Deep Packet Inspection (DPI) or Web Application Firewalls (WAF).
2. **Encrypted Traffic Drift:** With TLS 1.3 / HTTPS encryption, packet sizes and timing are the only available signals; sophisticated attackers can pad packet sizes to mimic benign browsing.
3. **Concept Drift:** As network protocols and attack signatures evolve, models must be periodically retrained using fresh traffic captures.
